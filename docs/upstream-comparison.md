# 相对上游的改进与可验证边界

比较对象固定为 [上游基线提交](https://github.com/yJie05up/adversarial-review/tree/e2d184246fb9d355ac8a6e5157dd26791d2f525d)。该提交包含 SKILL、README 和审查参考文档，没有可执行评测程序或自动测试。

| 方面 | 上游基线 | 本次改造 |
|---|---|---|
| 使用方式 | 由支持子代理的助手执行提示词 | 保留助手审查流程，新增无需模型账号的本地 CLI |
| 检查证据 | 自由文本 | 输入校验、结构化记录、导出报告和自动化回归测试 |
| 判决真实性 | PASS 要求非空撤回项 | 不设缺陷/撤回配额，允许零缺陷；证据不足单独说明 |
| 风险判断 | 低置信度整体降为 DEBT | 严重性与证据确定性分别判断，关键疑点待复核，不自动放行 |
| 审查维度 | 宣称五轴穷尽 | 五轴作为可扩展启发式，按业务补充隐私、评测与运营指标 |
| 失败模式 | 主要依赖模型执行规则 | 显式拒绝无效输入、检查覆盖率与门禁、测试边界输入 |
| 交付 | 文字审查意见 | JSON、Markdown、可在浏览器打开的 HTML 报告 |
| 场景 | 任意完成物 | AI 产品质量评测或产品运营实验，职责可演示 |

这张表比较已实现的使用方式与验证能力，不证明本工具的判断全面优于上游，也不证明 AI 本身更准确。自动检查验证字段与规则，不能证明证据内容真实；人工仍需核对证据来源。CLI 不执行发布、修改生产配置或联系用户。

## 原方法中保留的部分

将结论拆为可核验的主张；让另一位审查者查看原始材料；给问题保留证据、影响和复验路径。不同审查者有助于降低共同盲点，但不能保证独立性或正确性。

## 本次有意修正的部分

不引用“全绿审查 99% 没有认真审”等缺乏数据的数字；不要求为了通过而制造撤回项；不把报错一概当作低优先级；不把未知风险自动当作可接受风险；不把固定分类写成形式化的完备性证明。
